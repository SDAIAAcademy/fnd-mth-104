Read the result

A permutation test of a new checkout layout gives p = 0.21 on 40 shops. A manager writes: "the layout has no effect". What is the best correction?

"The data cannot tell at this size; the interval for the effect is wide."
"There is a 79% chance the layout works."
"The layout makes things worse."
"Retest at α = 0.01 to confirm there is no effect."
Why. Not enough evidence of an effect is not evidence of no effect; the interval shows how much is still possible.

Block A · where it happens

Dashboards, subgroup tables and "we also looked at" paragraphs run many tests

  • One test per product line, region or customer segment
  • Many outcomes for one change: sales, visits, basket size, returns
  • Results reported only when they pass, so the reader never sees the count
What goes wrong. A "finding" that is one of twenty tests is about as surprising as one heads in twenty coin tosses.

Ask for a dashboard the room uses that colours cells by significance. How many cells? How many coloured cells would chance alone give?

Block B · what to control

Control the chance of any false finding, or the share of false findings

Family-wise error rate

The chance of at least one false finding in the family. Bonferroni: reject when p ≤ α / m. Holm: the same guarantee, step by step, more power.

False discovery rate

The expected share of false findings among all findings. Benjamini-Hochberg: largest k with p₍ₖ₎ ≤ k α / m.

Family-wise control suits a few claims that each lead to action; false-discovery control suits screening many candidates for follow-up. Choosing the family and gatekeeping between primary and secondary claims are in SPC-STA-201. Sources: NIST/SEMATECH e-Handbook of Statistical Methods, section 7.4.7.3, Bonferroni's method; SciPy documentation of scipy.stats.false_discovery_control, which implements the Benjamini-Hochberg procedure and cites Benjamini and Hochberg (1995); statsmodels documentation of multipletests for Holm.

Checkpoint

Which procedure fits the purpose?

A team screens 300 product ideas from survey data to pick some for a costly follow-up trial; a few false picks are acceptable if most picks are real. Which control fits?

No correction: each test is at 5%
Benjamini-Hochberg, controlling the share of false picks
Bonferroni, controlling any false pick at all
Test each idea at α = 0.01 instead
Why. Screening for follow-up tolerates a small share of false picks; that is what the false discovery rate controls.

Block C · forking paths

One test can hide many: every choice made after seeing the data is a fork

  • Which outcome: units, value, share of baskets
  • Which units: all branches, large ones, one sector
  • What to do with outliers, which weeks, which test

No fishing needed

Each choice can be reasonable. Making them after looking still inflates the false-finding rate, even when only one test is run.

Sources: Gelman and Loken (2013), The garden of forking paths, whose point is that the problem arises even without conscious fishing. The lab measures it on noise with eight reasonable paths.

Block C · the cure

Write the analysis down before you look, and report every test you ran

Before

Question, outcome, groups, test, outlier rule, family of claims.

During

Any change to the plan is logged with its reason.

After

Report the planned results first; label the rest exploratory.

Checkpoint

Name the problem

A summary reports that a staff-training course "significantly reduced errors among evening-shift staff over 40 (p = 0.03)". The full data covered all shifts and ages; no subgroup was planned. What is the main problem?

Evening staff may be less careful
None: p = 0.03 is below 0.05
The subgroup is too small for a permutation test
A forking path: the subgroup was picked after seeing the data
Why. Many subgroups could have been reported; choosing the one that passed makes p = 0.03 far less surprising than it looks.

Answer D. This is the shape of the LO3 critique: name the problem and its effect on the conclusion.

From the solution run of lab 7.1 (Monte Carlo error about ±0.03 on the 0.627, two standard errors). Theory for 20 independent tests: 0.642. With every line null, any finding is false, so the family-wise rate and the false discovery rate are the same quantity. Bonferroni and Holm flag exactly the same dashboards (both need the smallest p at or below 0.05 / 20); Benjamini-Hochberg can add a dashboard whose k-th smallest p is below k × 0.05 / 20, which happened in none of these 1,000. The corrected rates sit below 0.05 because the simulation uses 500 shuffles per test: the smallest possible p, 1 / 501, is just under 0.05 / 20, so a line passes Bonferroni only when it beats every shuffle. The real dashboard's two findings, L07 (p = 0.030) and L10 (0.048), vanish under every correction.

Week 7 · wrap-up

Three things to keep

Count the tests

Twenty true nulls give a finding most of the time.

Correct for the family

Holm for decisive claims, BH for screening.

Fix the path first

Choices made after looking are hidden tests.

The responsible-use line of the course: participants have now seen how many false findings uncorrected testing produces. Ask them to say it in one sentence for their manager.
